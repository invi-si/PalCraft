# PalCraft architecture

The installed UE4SS mod is `Mods/NativeMods/UE4SS/Mods/PalCraft`. `Scripts/main.lua` reads `config.ini` before optional factories. Modules remain at the mod root to preserve existing asset and sidecar lookup contracts. PalSchema directories are `PalCraft_*`; paks live under `Pal/Content/Paks/~mods/PalCraft/`. Internal `/Game/Minecraft*` paths and saved item/Pal IDs remain stable.

`release/modules.json` inventories every Lua file, schema pack and legacy pak, records dependencies and assigns Core, HUD & Skins, Islands & Animals, Map Art or the strip category. Shared pure code and data belong in Core; loading a library does not start its service. `feature_flags.lua` reads `packs = hud_skins,islands_animals` and `map_art = 0` or `1`. Unknown pack names and invalid booleans are rejected.

With HUD & Skins selected, the existing entry/lifecycle code starts its screens, player rig, controls, building and equipment. World factories load only when Islands & Animals is selected. Islands-only dispatches to `native_pack.lua`, which admits a stable living pawn, runs the island/native creature/boss/village services and leaves native HUD, inventory and ordinary controls available. The native village exchange adapter uses the same durable transaction engine and native containers. Its contextual text/input interface requires native acceptance. Core-only starts no optional service.

`timers.lua` retains one master tick and registers specific native callbacks once. Epoch changes forget Lua wrapper references and reacquire level-owned actors; they do not destroy chunk actors during respawn or title return. Asset factories are gated before object/asset access. The installer reconstructs textures and fonts from `assets/minecraft/` and patches the hash-bound blank paks. Original cooked materials and samplers resolve these textures for both Lua and native consumers. General runtime texture/material binding and preload queues are disabled. Runtime imports remain only for personal player skins and the original Bram/Rina skins. Jar DATA adapters remain enabled; missing optional runtime audio may be silent.

Map markers are independent of map artwork. Modified Palworld map-art packages are excluded from distributable builds. The map-art payload slot and flag remain reserved for a redistributable implementation. Changing mounted pak selection requires restarting after installer pack selection.

World sidecars stay directly in the mod folder. Builds are stored as `blocks-<32-hex-world-id>.json`, with validated sequence/schema/world fields and recovery generations. Other files cover pending inventory, beds/entry recovery, hotbar, loot, travel settings, map marker ownership and village trade journals. Global UI and skin preferences use their existing JSON files. `legacy_paths.lua` reads a legacy MinecraftBlocks family only when every new generation is missing/empty; writes stay under PalCraft. `installer/migrate-legacy.ps1` copies world sidecars/settings/user skins, checks hashes, and preserves both originals when a populated destination differs.

The payload builder stages a fresh tree, applies provenance exclusions and code stripping, checks leaks, writes per-file SHA256, and verifies the ZIP. It never deploys or launches the game. The public-source exporter starts with a new directory and no Git history; it includes only cleared code, schema, tools, documentation and original source art.
